한국어 개인정보처리방침

1. 앱과 개발자

Duo Flex: Foldable Animation은 HTLee Studio의 폴더블 화면 효과 앱이다. 앱 내 회원 계정이나 개발자의 별도 분석 SDK는 사용하지 않는다. Google Mobile Ads와 UMP를 포함하며 앱 하단에 배너 광고를 표시한다. 개발용 빌드는 테스트 광고를 사용한다.

2. 접근하는 정보와 사용 목적

  • 화면 이미지: 최초 사용 또는 고지 버전 변경 시 전체 설명을 읽고 연결 및 권한 페이지에서 체크박스와 ‘동의하고 저장’을 선택하면, 이후 사용자가 효과를 켤 때 기기 내부 연결을 통해 홈과 지원 앱의 화면 이미지를 읽어 블러 효과를 만든다. 픽셀은 메모리에서만 처리한다. 스크린샷 파일로 저장하거나 개발자·외부 서버에 전송하지 않는다. 잠금·설정·권한·Duo Flex 화면에서는 캡처와 효과를 일시 정지한다. 보호된 콘텐츠를 포함하도록 캡처 옵션을 켜지 않으며 보호된 결과는 제외한다.
  • 접근성 정보: 별도 고지·동의 후 허용한 접근성 서비스는 창 종류, 화면·창 식별자, 패키지·창 클래스, 위치·크기·포커스 등의 메타데이터로 효과 위치와 숨김 여부를 판단한다. 창 식별 이벤트가 없을 때 최상위 항목의 앱 이름만 확인하고, 하위 항목을 미리 가져오거나 탐색하지 않는다. 접근성 노드의 글자·입력 내용은 읽지 않고 제스처를 실행하지 않는다. 화면 픽셀은 접근성 노드가 아니라 같은 APK의 기기 내부 연결 코드에서 얻는다.
  • 접힘·기기 정보: 지원 여부와 연결 상대를 확인하기 위해 모델·Android 버전·기본 사용자 여부를 확인한다. 접힘 정보와 화면 상태를 효과에 사용한다. 원문 로그를 보고서로 저장하거나 전송하지 않는다.
  • 연결 정보: 최초 페어링 코드와 포트를 입력한다. 코드는 저장하지 않는다. 재연결용 앱 키와 상대 확인 정보는 Android Keystore를 이용해 암호화하고 앱의 백업 제외 영역에 보관한다. 최근 연결 포트와 효과·언어 설정을 기기에 저장한다. 화면 접근에 동의한 고지 버전 번호만 기기에 저장하며, 동의한 화면 내용·페어링 코드는 저장하지 않는다.
  • 로컬 진단: 앱 실행 결과는 완료 시간, 종료 이유, 소요 시간, 프레임·응답·자원 개수 등의 제한된 수치와 상태만 저장한다. 최근 결과·최근 정상·최근 실패와 실패 이력 최대5건, 실행 중 중단 진단을 위한 제한된 기록을 보관하며 각 파일은 16KiB 이하다. 이미지·입력 내용·창 메타데이터·원문 로그·페어링 코드·키를 보고서에 넣지 않는다. 효과 시작·화면 상태·일시정지·연결 유실·종료/정리 등의 고정 이벤트와 USB 디버깅·Wi-Fi·화면·잠금 상태를 최대64개/최근3일/24KiB로 로컬에 보관한다. 반복 상태는 합치며 기록/조회 때 기간을 정리한다.
  • 선택적 문제 신고: 설정에서 사용자가 증상을 적고 모델·Android/API·앱 버전·기존 진단·제한된 이벤트를 확인한 뒤 메일/공유 앱으로 전달할 수 있다. 자동 업로드하거나 자동 전송하지 않는다. 확인한 내용만 최대64KiB 텍스트 첨부로 만들고 기기 캐시에 최대5개 보관한다. 다음 첨부 생성 시7일 지난 파일을 지운다. 증상에는 개인정보·페어링 코드·비밀번호를 적지 않는다. 이메일 전송 시 문의 항목에 따라 처리하며 메일 앱이 만든 사본은 그 앱의 방침과 사용자 선택에 따른다.

3. 통신과 제3자

INTERNET 권한은 무선 디버깅의 연결 포트 발견과 이 기기 내부(127.0.0.1)의 TLS 연결, Google 광고 서비스 통신에 사용한다. Wi-Fi에서 Android의 로컬 서비스 발견을 사용하므로 네트워크 통신 자체가 전혀 없다고 설명하지 않는다. 화면 처리 도우미는 동일 APK 코드이며 외부 앱 또는 클라우드 캡처 서비스가 아니다. 화면 이미지와 로컬 효과 진단 보고서는 개발자 서버·광고·분석 업체에 자동 전송하지 않는다. 사용자가 검토해 직접 보내는 문제 신고는 별도의 이메일 문의 처리다. 아래의 광고 SDK 자체 진단과 구분한다. 사용자가 문의할 때 제공한 내용은 해당 문의 채널의 별도 취급 절차를 따르므로 이메일 문의 항목에 따라 처리한다.

4. 광고 정보 처리

광고 SDK가 없는 이전 버전에는 아래 광고 처리가 적용되지 않는다. Google 광고 SDK는 광고 제공·측정·진단·부정 사용 방지를 위해 IP 주소(대략적인 위치 추정 가능), 앱·광고 이용 정보, 진단 정보와 기기/계정 식별자 등을 Google에 전송할 수 있다. 테스트 광고도 네트워크 요청을 하므로 ‘외부 수집 없음’으로 설명하지 않는다. 광고가 포함된 현재 버전은 Android 광고 ID와 AdServices ID/Attribution/Topics 권한을 선언하지 않는다. 이 조치가 다른 SDK 정보 처리까지 없애지는 않는다. 화면 이미지·접근성 창 정보·페어링 코드/키·로컬 효과 진단은 광고 SDK에 전달하지 않는다.

앱 설정의 ‘광고 및 개인정보’에서 관련 안내와 Google 개인정보처리방침을 볼 수 있다. Google의 처리·보관·선택은 Google 방침을 따른다. 배포용은 UMP로 광고 요청 가능 여부를 확인하고 필요한 동의 폼과 설정의 선택 변경 기능을 제공한다. 개발용 테스트 모드에서는 이 폼을 호출하지 않는다. 광고 동의 안내와 선택 변경 항목의 표시 여부는 지역·기기와 Google의 동의 상태 판단에 따라 달라질 수 있다. 광고 오류가 나면 광고를 표시하지 않고 효과 기능과 별개로 처리한다.

5. 보관·종료·삭제

효과 OFF·권한 해제·연결 종료 때 메모리 이미지와 효과 창, 임시 화면 요청을 정리한다. 설정의 ‘화면 효과 동의 철회’로 동의를 지우고 실행 중 효과를 중지할 수 있다. 다음 시작에는 다시 명시적 동의를 받는다. 앱 연결 키는 연결 설정에서 삭제할 수 있다. Android 무선 디버깅의 앱에 표시된 페어링 이름(duoflex-<12hex>@local) 등록은 별도로 사용자가 삭제해야 한다. 앱 데이터 삭제 또는 앱 제거로 로컬 키·설정·진단 기록을 지울 수 있다. 접근성·다른 앱 위 표시·알림 권한도 Android 설정에서 해제할 수 있다. 사용 종료 안내에서 무선 디버깅·개발자 옵션을 끄고 삼성 자동 차단을 다시 켜는 절차를 제공한다.

English Privacy Policy

1. App and developer

Duo Flex: Foldable Animation is a foldable screen-effects app by HTLee Studio. It has no in-app user accounts or separate developer analytics SDK. Advertising-enabled versions include Google Mobile Ads and UMP and display a footer banner. Development builds request test ads. Earlier versions without the advertising SDK do not perform this advertising processing.

2. Information accessed and why

  • Screen images: On first use or after the disclosure version changes, the user reads the full notice and checks the box and selects “Agree and save” on the connection and permissions page. Later, the user can turn effects on directly using the locally stored consent version. Local connection code reads home and supported-app images to create blur effects. Pixels stay in device memory, are not saved as screenshot files, and are not sent to the developer or external servers. Capture and effects pause on lock, settings, permission and Duo Flex screens. Capture options do not enable protected content, and protected results are excluded.
  • Accessibility information: After a separate disclosure and consent, the accessibility service uses window type, display/window identifiers, package/window class, position, size and focus metadata to position and hide effects. When a window-identification event is missing, only the root item's app name is checked, without prefetching or traversing child items. It does not read text or inputs through accessibility nodes or perform gestures. Screen pixels come from the same APK's local connection code, not accessibility nodes.
  • Fold/device information: Model, Android version and primary-user status are checked for compatibility and connection identity. Fold information and display state drive effects. Raw logs are not saved as reports or transmitted.
  • Connection information: A pairing code and ports are entered initially. Codes are not saved. Reconnection keys and peer-verification data are encrypted using Android Keystore and stored in app storage excluded from backup. Recent connection ports, effect preferences and language are saved locally. Only the accepted screen-access disclosure version is retained; screen content and pairing codes are not retained as consent records.
  • Local diagnostics: Completion time, reason, duration and bounded frame, response and resource counts are retained locally. Bounded files hold the latest, latest normal and latest failed result, up to five recent failures and a running-session marker, each limited to 16KiB. Reports exclude images, input content, window metadata, raw logs, pairing codes and keys. A local event file retains up to 64 fixed events from the last 3 days, capped at 24 KiB: effect start, screen state, pause, connection loss, stopping/cleanup and USB debugging, Wi-Fi, screen and lock states. Duplicate states are combined; age is checked when recording or reading.
  • Optional problem reports: In Settings, users may describe a problem, review the device model, Android/API and app version, existing diagnostics and limited events, then hand the report to a mail/sharing app. Nothing is uploaded or sent automatically. The reviewed text attachment is capped at 64 KiB. Up to 5 attachments remain in device cache; files older than 7 days are removed when the next attachment is created. Do not enter personal information, pairing codes or passwords. Sent emails follow the support section below; copies created by mail apps follow their policies and user choices.

3. Communication and third parties

The INTERNET permission supports local wireless-debugging port discovery, a TLS connection to this device (127.0.0.1) and communication with Google advertising services. Android local-service discovery uses Wi-Fi, so the app does not claim that no network communication occurs. The processing helper runs code from the same APK; it is not a separate third-party capture app or cloud service. The app does not automatically send screen images or local effect diagnostic reports to developer, advertising or analytics servers. Optional reports reviewed and sent by the user are handled as email support. This is separate from the advertising SDK diagnostics described below. Voluntarily submitted support information is handled as described in the email-support section.

4. Advertising data

This advertising processing does not apply to earlier versions without the advertising SDK. Google's advertising SDK may send IP addresses (which can be used to estimate approximate location), app/ad interaction information, diagnostics and device/account identifiers to Google for ad delivery, measurement, diagnostics and fraud prevention. Test ads also involve network requests and advertising SDK data processing. Advertising-enabled versions covered by this policy do not declare Android advertising-ID and AdServices ID/Attribution/Topics permissions. This does not eliminate other SDK data processing. Screen images, accessibility window metadata, pairing codes/keys and local effect diagnostics are not passed to the advertising SDK.

“Ads and privacy” in app Settings provides the notice and a link to Google's Privacy Policy. Google's policy governs its processing, retention and choices. Release builds use UMP to check whether ads can be requested and show applicable consent forms and privacy options in Settings. Development test mode does not invoke these forms. The availability of consent forms and privacy options depends on the region, device and Google's consent-status determination. Ad load failures are handled separately from screen effects.

5. Retention, stopping and deletion

Turning effects off, revoking permissions or losing the connection triggers cleanup of memory images, effect windows and temporary display requests. “Revoke screen-effects consent” in Settings removes consent and stops running effects. The next start requires affirmative consent again. Connection keys can be deleted in the app. The user separately removes the entry matching the pairing name shown in Duo Flex (duoflex-<12hex>@local) from Android Wireless debugging. Clearing app data or uninstalling removes local keys, preferences and diagnostic records. Accessibility, overlay and notification permissions can be revoked in Android Settings. The end-use guide explains disabling wireless debugging and developer options, then restoring Samsung Auto Blocker.
